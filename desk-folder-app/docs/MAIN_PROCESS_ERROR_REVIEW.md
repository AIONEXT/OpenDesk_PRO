# Code Review & Root-Cause Fix Report: `Error: A JavaScript error occurred in the main process`

## 1. Root Causes Identified in `src/main/main.ts` & Build Pipeline

| # | Root Cause | Why It Triggered the Main-Process Error Dialog | Resolution Applied in `main.ts` & `apply-v2.sh` |
|---|---|---|---|
| **1** | **Duplicate `ipcMain.handle()` on Hot-Reload** | When `vite-plugin-electron` reloads the main process in dev mode, calling `ipcMain.handle(channel, ...)` a second time throws `Error: Attempted to register a second handler for '...'`. | Replaced direct `ipcMain.handle` calls with a safe `registerIpc(channel, fn)` wrapper that calls `ipcMain.removeHandler(channel)` first. |
| **2** | **Top-Level `app.dock.hide()` & `app.getPath()` Before Ready** | Calling `app.dock.hide()` and `app.getPath('documents')` at module load time (before `app.whenReady()`) can throw synchronously during startup. | Moved `app.dock.hide()` inside `app.whenReady()` and wrapped path resolution in lazy `getSafeUserDataPath()` and `getDefaultWorkspacePath()` helpers. |
| **3** | **`path.join(process.resourcesPath, ...)` in Dev Mode** | In dev environments where `process.resourcesPath` is undefined or `trayTemplate.png` is empty/corrupt, `createTray()` threw an unhandled promise rejection inside `app.whenReady().then(async () => ...)`. | Added `typeof process.resourcesPath === 'string'` guard, validated `!loaded.isEmpty()`, and added a fallback to `nativeImage.createEmpty()` with `tray.setTitle(' 📂 DeskFolder')`. |
| **4** | **`screen.getPrimaryDisplay()` & `setBounds()` Validation** | Accessing Electron's `screen` module before `app.isReady()` or passing non-integer/NaN values to `mainWindow.setBounds()` throws a native C++ bridge `TypeError`. | Guarded `getDropdownBounds()` with `if (!app.isReady())` and clamped all `x, y, width, height` values with `Math.round()`. |
| **5** | **Unhandled Promise Rejection on `loadURL` / `loadFile`** | In Electron 28, `mainWindow.loadURL()` returns a Promise that rejects if the Vite dev server is still warming up on first launch, triggering the native error modal. | Attached `.catch()` with a 400ms automatic retry for `VITE_DEV_SERVER_URL` and `.catch()` on `loadFile()`. |
| **6** | **Stale `dist-electron/` or `"type": "module"` in `package.json`** | If `package.json` wasn't synced or stale `dist-electron/main.js` remained from a previous build, Node threw `ReferenceError: require is not defined in ES module scope`. | Updated `apply-v2.sh` to kill stale Electron processes, sync `package.json`, wipe `dist/` and `dist-electron/`, and rebuild cleanly. |
| **7** | **Uncaught Exception Modal Shield** | Electron's default `uncaughtException` / `unhandledRejection` behavior blocks the UI with a native macOS error alert. | Added `process.on('uncaughtException')` and `process.on('unhandledRejection')` handlers at the top of `main.ts`. |
